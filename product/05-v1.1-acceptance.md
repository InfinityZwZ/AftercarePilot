# AftercarePilot V1.1 产品验收与版本复盘

验收日期：2026-11-12。需求基准：[V1.1 PRD v0.1](AftercarePilot_V1.1_PRD.md)。对照基线：[V1.0 审计](00-v1-baseline.md)，Git `1b0276b`。被测版本为完成 FR-01～FR-06 的本地工作区。

## 1. 目标与结论

V1.1 的目标是让客服进入请求后，能识别当前状态和下一步，核对订单、规则与政策，理解创建工单或确认草稿的后果，并在信息不足时继续处理原请求。

**产品验收结论：有条件通过，建议作为作品集的合成数据演示版本。** A 正常建单和 B 未签收仅确认草稿完成闭环。C 缺单号能在首屏找到查找入口，同一请求补录成功，但首次自动化连续点击没有等到回填完成，产生了一版重复待补充记录。另有首屏操作可达性、草稿内容和申请原因来源标注的问题。工程安全用例有既有回归证据，正式业务试点和真实用户体验收益未验证。

## 6. 环境、方法与工程安全证据

Windows 本机 Chrome 与 Playwright，Streamlit → FastAPI → 真实本地 PostgreSQL 专用验收库 `aftercare_v11_acceptance_demo`，独立写入和只读角色，真实只读 MCP。Clock 固定为 2026-10-09 12:00 UTC，页面显示本机时间。验收入口复用仓库的验证 API 和业务 UI，验收专用 FakeLLM 将 ORD-1002 路由到仅回复分支。供应商调用在验证 API 中被禁止。通过页面操作配合只读 API 计数及独立工单读取验证结果。

既有工程全量运行命令为 `python -m pytest -q --tb=short`，结果 **405 通过、1 项 Authlib 弃用警告，210.01 秒**。本轮复核证据与断言，并新增浏览器验收记录，未重复全量运行。

## 7. 发现的问题与严重程度

| 编号 | 严重程度 | 观察与影响 |
| --- | --- | --- |
| P1-01 | 中 | **下一步可见，但主要操作未进首屏。** A/B 首屏可核对依据，需下滚约 335 px 才能到按钮上缘。C 查找表把手动补录和提交按钮推到首屏下方。可能增加寻找操作的成本，尚无真人测试数据。 |
| P1-02 | 中 | **申请原因来源标注过强。** B 原话为「已经不需要了」，固定 FakeLLM 提供「商品故障」，页面却显示「申请原因（客户提供）」。未签收规则仍正确拒绝，差异来自本次固定脚本，页面标签也未区分客户原话与模型提取。此次样本不支持对真实模型提取准确率的结论。 |
| P1-03 | 中 | **常规演示草稿仍混入内部状态。** A/B 固定脚本草稿出现「待审核草稿」「批准后可提交」「目前没有发生退款或发送消息」。B 还与仅回复的业务结果不一致。C 的确定性追问已正确分离。作品集截图保留原样，讲解时说明是模拟输出及待改点。 |
| P2-01 | 低，需复现 | **快速补录的一次失败。** 首次自动化点击选入后立即提交，保存了仍无订单号的输入并生成重复待补充版本。第二次等待回填可见后成功。当前证据确认了现象，未定位是前端重跑时序还是测试驱动触发过快。 |

本轮未观察到越过审批建单、错误退款提示、错误发送提示或重复工单。P1 项属于理解、内容与操作可达性问题，影响对产品体验完成度的判断。
